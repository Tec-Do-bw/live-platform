# 单一权威源原则

## 触发条件

创建或编辑技术文档时。

## 规则

每份技术文档只在一个位置维护，其他位置通过路径引用，禁止复制副本。

## 正确做法

```markdown
# ✅ 在 CLAUDE.md 中引用
业务规则详见 `.claude/rules/login-callback-spec.md`

# ✅ 在代码注释中引用
# 登录回调规格详见 .claude/rules/login-callback-spec.md

# ❌ 错误：复制内容到多个文件
# CLAUDE.md 和 README.md 都复制了完整的登录回调规格
```

## 适用场景

- API 接口规范
- 业务规则文档
- 技术决策记录
- 架构设计文档
- 配置说明

## 例外情况

- 不同层级的 CLAUDE.md（根 vs 子项目）：子项目只记录特有规则，通用规则引用根文档
- 示例代码：可以在多处展示，但需标注"示例"

## 原因

多份副本导致维护成本倍增，容易出现版本不一致，造成混乱和错误决策。单一权威源确保信息准确性和可维护性。
