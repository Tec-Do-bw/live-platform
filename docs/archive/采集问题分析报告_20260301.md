INFO     | base.py:138 - 访问页面数: 1, 拦截API数: 0, 发送数据数: 0

**发生时间点：**
- 2026-02-28 19:32 — `tiktok.py:397` sessionid cookie 缺失

### 问题 2（严重）：Shopee 账号配置文件缺失，导致自动重登失败

**发生频率：** 极高频（21:14 ~ 21:18 期间，连续约 20+ 次）

**日志特征：**
```
WARNING  | shopee.py:440 - 关键登录Cookie缺失或无效
WARNING  | shopee.py:84  - 检测到账号已登出，开始执行模拟登录...
ERROR    | shopee.py:99  - 未找到账号配置，请检查 resource/accounts/shopee_accounts.json
ERROR    | base.py:128   - 检测到账号登出，停止采集
```

**原因：**
`resource/accounts/shopee_accounts.json` 文件不存在或配置为空，导致 Shopee 在 Cookie 失效时无法自动重登。

**影响：**
最终 Shopee 采集结果虽然显示 28/28，但这些失败均为 Cookie 在采集完成后才触发失效（采集已完成），不影响本轮结果。但若 Cookie 在采集前或采集中失效，数据将完全丢失且无法恢复。

**建议修复：**
- 检查并配置 `resource/accounts/shopee_accounts.json`
- 在 `shopee.py:99` 处增加告警通知，避免静默失败

---

### 问题 3（中等）：browserapi.py 频繁触发"Too many request per second"限流

**发生频率：** 中频（全天多个时间段，每次连续 3~5 次报错）

**日志特征：**
```
ERROR | browserapi.py:137/138 - 查询环境失败: Too many request per second, please check (第1次尝试)
```

**发生时间段：** 18:14、18:17、18:18、18:49、19:17、19:22、20:18、21:13 等（多次爆发）

**原因：**
多账号并发查询 AdsPower 环境 API（分组环境列表）时，触发平台接口频率限制。

**影响：**
触发重试机制，延迟采集启动，但目前有重试逻辑能最终成功（第1次尝试后会自动重试）。

**建议修复（优化）：**
- 批量启动多分组查询时增加请求间隔（建议 500ms ~ 1s）
- 或限制并发查询分组的数量

### 问题 4（中等）：TikTok replay 列表容器元素类名过期

**发生频率：** 中频（03-01 多次，在 06:01、18:54、19:49、20:17、20:54 等时间段）

**日志特征：**
```
WARNING | tiktok.py:438 - 未找到 replay 列表容器元素（类名可能已过期），跳过滚动
```

**原因：**
TikTok 前端页面 DOM 类名已更新，`tiktok.py:438` 处的 CSS 选择器与实际页面不一致。

**影响：**
跳过滚动加载更多 replay 数据，可能导致历史直播数据抓取不全（只抓取到首屏数据）。

**建议修复：**
- 更新 `tiktok.py:438` 处的 replay 列表容器 CSS 选择器，需重新抓包确认当前类名
