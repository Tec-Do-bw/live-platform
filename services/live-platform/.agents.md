# live-platform 架构实施记录

## 关键决策（2026-06-23）

### 1. Apollo 配置标准化
- **模板来源**: `D:\SpiderCode\prod\spider-back-end\core\apollo`（团队标准）
- **环境变量**:
  - `APOLLOID`: Apollo App ID，默认 `'live-spider'`
  - `APOLLO_URL`: 配置中心地址，默认 `'http://dev-apollo.tec-develop.com'`
  - `DEPLOY_ENV`: 集群/环境，默认 `'default'`
- **多环境切换**: Zadig 注入环境变量即可切 dev/prod，无需改代码

### 2. MySQL → Redis 种子同步
- **权威源**: MySQL 表 `live_streaming_room`（对齐 live-monitor 生产逻辑）
- **SQL**: 
  ```sql
  SELECT room_id, room_url, allocation_status, collection_id, platform
  FROM live_streaming_room
  WHERE local_status = 1
  ```
- **Redis key 策略**: 保持 `live:collection:{collection_id}` 设计（collection_id 一定有值）
- **同步周期**: 5 分钟（对齐 live-monitor）
- **下线处理**: 直接删 Redis 投影（对齐 live-monitor 软删除语义）
- **消费模型**: 先不做 allocation_status 抢占逻辑，只写状态（isLive/roomId/flvUrl/status）

### 3. 配置清单（Apollo dev 已有）
**MySQL 连接（对齐 live-monitor）**:
- `devSqlHost`
- `devSqlPort`
- `devSqlUser`
- `devSqlPassword`
- `database`

**可选配置**:
- `mysqlSyncIntervalSeconds`: 种子同步周期（秒），默认 300

## 对齐生产（live-monitor）

### 已对齐
- ✅ MySQL 连接配置 key 口径（devSqlHost/User/Password/database/Port）
- ✅ 种子 SQL（补充 collection_id + platform 列）
- ✅ 同步周期（5 分钟）
- ✅ 下线处理（软删除：直接删 Redis）
- ✅ Redis 连接配置 key（redisHost/Port/Password/Db）

### 差异点
- live-monitor: 房间状态在内存 `all_Live_Room_dict`，跨节点 HTTP 同步
- live-platform: 房间状态在 Redis，状态机在内存（单节点）
- live-monitor: `allocation_status` 抢占分配（/get_roominfo 领取 → /report_roominfo 心跳）
- live-platform: 暂不实现抢占，只写状态（下游将由 live-crawler 提供 batch 接口）
