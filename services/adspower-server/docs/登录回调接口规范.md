# 登录回调接口规范

> 本文档定义了浏览器登录监控服务的回调接口规范，供其他项目参考和调用。

---

## 1. 概述

登录回调机制用于在浏览器登录流程结束后，通知后端服务登录结果。支持三种登录状态：成功、失败、关闭。

### 1.1 调用链路

```
前端 → 后端 → FastAPI（本服务）→ 登录监控 → 回调后端
```

### 1.2 回调时机

| 场景 | 触发点 | 回调状态 |
|------|--------|----------|
| 登录成功 | 检测到登录成功并验证店铺匹配 | `success` |
| 登录超时 | 超过配置的超时时间未完成登录 | `error` |
| 店铺不匹配 | 登录成功但店铺ID与预期不符 | `error` |
| 监听异常 | 登录监听过程发生异常 | `error` |
| API 关闭 | 调用关闭浏览器 API | `closed` |
| WebSocket 断开 | 前端 WebSocket 连接断开 | `closed` |
| 应用关闭 | 服务进程关闭 | `closed` |

---

## 2. 回调接口规范

### 2.1 接口定义

```
POST {CALLBACK_URL}
Content-Type: application/json
accessToken: {ACCESS_TOKEN}
```

### 2.2 配置项

| 配置项 | 环境变量 | 默认值 | 说明 |
|--------|----------|--------|------|
| 回调地址 | `LOGIN_CALLBACK_URL` | - | 后端接收回调的 URL |
| 访问令牌 | `LOGIN_CALLBACK_ACCESS_TOKEN` | - | 请求头中的认证令牌 |
| 登录超时时间 | `LOGIN_TIMEOUT_SECONDS` | 900 | 登录超时时间（秒） |
| 成功后关闭延迟 | `LOGIN_SUCCESS_CLOSE_DELAY_SECONDS` | 5 | 登录成功后延迟关闭浏览器（秒） |
| 失败后关闭延迟 | `LOGIN_FAILED_CLOSE_DELAY_SECONDS` | 3 | 登录失败后延迟关闭浏览器（秒） |
| 超时后关闭延迟 | `LOGIN_TIMEOUT_CLOSE_DELAY_SECONDS` | 3 | 登录超时后延迟关闭浏览器（秒） |

### 2.3 请求 Payload

```json
{
    "login_status": "success|error|closed",
    "media": "shopee|tiktok",
    "validate_id": "123456",
    "collection_id": "profile_xxx",
    "reason": "timeout|shop_mismatch|listen_error|api_close|ws_disconnect|app_shutdown",
    "session_id": "session_xxx",
    "shop_id": 123456
}
```

### 2.4 字段说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `login_status` | string | 是 | 登录状态：`success`/`error`/`closed` |
| `media` | string | 是 | 媒体类型：`shopee`/`tiktok` |
| `validate_id` | string | 是 | 预期的店铺ID（用于验证） |
| `collection_id` | string | 是 | 浏览器环境ID（AdsPower profile_id） |
| `reason` | string | 否 | 失败/关闭原因（见下表） |
| `session_id` | string | 是 | 本次会话ID |
| `shop_id` | int/null | 否 | 实际登录的店铺ID（成功时返回） |

## 3. 状态与原因对照表

### 3.1 login_status 三种值

| 值 | 含义 | 触发场景 |
|----|------|----------|
| `success` | 登录成功 | 检测到登录成功并验证店铺匹配 |
| `error` | 登录失败 | 超时、店铺不匹配、监听异常等 |
| `closed` | 主动关闭 | API关闭、WebSocket断开、应用关闭等（未完成登录流程） |

### 3.2 reason 字段说明

| reason | 含义 | 对应 login_status |
|--------|------|-------------------|
| `timeout` | 登录超时 | error |
| `shop_mismatch` | 店铺不匹配 | error |
| `listen_error` | 监听异常 | error |
| `api_close` | API 主动关闭 | closed |
| `ws_disconnect` | WebSocket 断开 | closed |
| `app_shutdown` | 应用关闭 | closed |

### 3.3 状态与 reason 组合

```
success + ""              → 登录成功
error + timeout           → 登录超时
error + shop_mismatch     → 店铺不匹配
error + listen_error      → 监听异常
closed + api_close        → API 主动关闭
closed + ws_disconnect    → WebSocket 断开
closed + app_shutdown     → 应用关闭
```

## 5. 登录监听机制

### 5.1 Shopee 登录监听

监听网络请求，匹配以下接口：
- `api/v2/login` - 获取登录后的 shop_id
- `subaccount/get_shop_list` - 获取子账号的店铺列表

验证逻辑：任一接口返回的 shop_id 匹配 validate_id 即为成功。

### 5.2 TikTok 登录监听

基于 Cookie 监听，检测 `multi_sids` Cookie：
- Cookie 存在且包含 validate_id → 登录成功
- Cookie 存在但不包含 validate_id → 店铺不匹配
- 超时未出现 Cookie → 登录超时

## 6. 回调优先级与去重

### 6.1 优先级规则

1. **登录结果回调优先**：登录成功/失败的回调优先于关闭回调
2. **首次触发原则**：每个 Session 只触发一次回调
3. **状态锁定**：一旦 `login_status` 被设置，后续关闭操作不再触发回调

### 6.2 去重机制

Session 对象包含 `login_callback_sent` 标志位：
- 首次回调成功后设置为 `true`
- 后续关闭操作检查此标志，已发送则跳过

```python
# 避免重复回调
if session.login_callback_sent:
    logger.info("Session 已发送过登录回调，跳过关闭回调")
    return
```

## 7. 回调触发点

### 7.1 登录监听触发

文件：`app/services/login_monitor.py`

```python
# 登录成功
await self._callback_backend(session, status="success", reason="", shop_id=shop_id)

# 登录超时

```

| 触发位置 | 文件 | reason |
|----------|------|--------|
| `/profile/close` API | `app/api/browser.py` | `api_close` |


## 8. 回调实现代码

### 8.1 回调发送方法

```python
async def _callback_backend(
    self,
    session: Session,
    status: str,
    reason: str,
    shop_id: Optional[int],
) -> None:
    callback_url = settings.LOGIN_CALLBACK_URL
    payload = {
        "login_status": status,
        "media": session.media,
        "validate_id": session.validate_id,
        "collection_id": session.profile_id,
        "reason": reason,
        "session_id": session.session_id,
        "shop_id": shop_id,
    }
    headers = {
        "Content-Type": "application/json",
        "accessToken": settings.LOGIN_CALLBACK_ACCESS_TOKEN,
    }

    if not callback_url:
        logger.info("未配置回调地址，跳过回调")
        return

    try:
        async with httpx.AsyncClient(timeout=10) as client:
            response = await client.post(callback_url, json=payload, headers=headers)
            session.login_callback_sent = True  # 标记回调已发送
    except Exception as exc:
        logger.warning("回调失败: %s", exc)
```

### 8.2 关闭回调方法

```python
async def callback_close(self, session: Session, reason: str = "closed") -> None:
    """关闭时回调通知后端"""
    # 避免重复回调（只有在回调真正发送后才跳过）
    if session.login_callback_sent:
        logger.info("Session 已发送过登录回调，跳过关闭回调")
        return

    await self._callback_backend(session, status="closed", reason=reason, shop_id=None)
```

## 9. 后端接口实现建议

后端接收回调时应考虑：

1. **幂等处理**：根据 `session_id` 去重，避免重复处理
2. **状态机校验**：验证状态转换合法性
3. **异步处理**：回调接口快速响应，后续处理异步执行
4. **日志记录**：记录所有回调请求便于排查

### 9.1 推荐的接口响应

```json
{
    "code": 0,
    "msg": "success"
}
```

### 9.2 错误处理

- HTTP 4xx/5xx：本服务会记录日志但不重试
- 超时（10秒）：本服务会记录日志但不重试
